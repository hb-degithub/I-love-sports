# 虚拟运动 使用说明

## 1. 安装

```bash
adb install -r dist/virtual-motion-0.17.0.apk
```

或直接把 APK 传到手机点击安装（需允许"安装未知来源应用"）。

## 2. 首次启动

1. 授予**定位权限**（Android 13+ 还会请求通知权限，用于前台服务常驻通知）
2. root 管理器（Magisk / KernelSU / APatch）会弹出授权请求 → **允许**
3. 面板上出现 `Root：已授权 ✓` 说明 root 通道正常
4. 若显示"模拟位置权限将在开始时自动授予"，点开始时 App 会自动执行
   `appops set com.vloc.motion android:mock_location allow`

> 不需要打开系统"开发者选项 → 选择模拟位置信息应用"，root 模式下直接通过 appops 授权。

## 2.1 定位与当前位置

- 首页地图**右下角的定位按钮**：读取设备真实位置，地图居中显示，并可直接：
  - 「添加为路径点」把当前位置加入路线
  - 「临时定位到这里」把注入位置设到当前真实位置
  - 「关闭」仅查看
- 菜单 →「定位到当前位置」同样可用
- 开工向导里的「用当前位置」也是实时定位（8 秒超时，失败会提示到室外/窗边重试）
- 模拟运行中读到的"当前位置"可能是注入坐标（测试 Provider 已接管），界面会提示

## 2.2 地图与坐标

- 默认地图源是**高德**（国内网络可用）；菜单 →「地图源」可切换高德卫星 / OpenStreetMap / Carto
- 地图一片空白：检查网络，或在开工向导点「手动坐标」直接输入经纬度
- 主界面菜单 →「输入坐标添加点」也可以在无地图时直接按经纬度加路径点

## 3. 规划路径

| 操作 | 效果 |
|---|---|
| 轻点地图 | **选点**：落下红色准星图钉，弹窗确认「添加为路径点」/「临时定位到这里」/「取消」 |
| 点选路径点图钉 | 查看坐标，可「删除该点」或「临时定位」到该点 |
| 长按图钉并拖动 | 微调路径点位置（折线实时跟随，松手保存） |
| 「撤销」 | 删除最后一个路径点 |
| 「清空」 | 删除全部路径点 |
| 长按地图 | 快速**临时定位**（不移动，直接确认） |
| 「临时定位」按钮 | 把定位设到地图中心点 |

底部「总里程」显示整条路径长度，路径至少 2 个点才能播放。

## 3.1 开工向导（推荐流程）

菜单 → **开工向导**，三步走完直接开始：

1. **① 选择目标位置**：在地图上点选，或「用地图中心」「用当前位置」
2. **② 选择模拟路线**：从路线库挑选，或使用主界面当前路径（不选路线则只做临时定位）
3. **③ 环境一致性**：
   - 点「采集周围基站与 Wi-Fi」→ 需要授予**定位**权限；**电话状态**权限用于部分机型读取完整小区身份（MCC/MNC/LAC/CID），拒绝时仍能采集到部分字段
   - 打开「模拟基站 / Wi-Fi 指纹」→ 隐藏模块会把快照回放到目标 App
   - 目标位置距离采集地 > 30 km 时建议打开「指纹与目标位置不匹配时隐藏基站信息」
4. 点「开始模拟」→ 前台服务启动、悬浮窗（如已开启）跟随

> 环境快照采集的是**当前设备真实环境**，仅在模拟期间通过本地 Provider 提供给隐藏模块；
> 不上传、不联网、停止模拟后立即失效。

## 4. 播放

1. 拖动「速度」滑块（1–120 km/h，播放中也能实时调整）
2. 需要反复走同一条路线时打开「循环播放」
3. 点「开始」
   - 前台服务接管系统 `gps` / `network` Provider
   - 每 200ms 写入一个插值坐标（含速度、朝向、精度）
   - 地图上绿色圆点实时跟随
4. 通知栏可「暂停 / 继续 / 停止」
   - **暂停**时不会停止上报：按 1Hz 持续上报同一坐标（真实 GPS 静止时本来就持续回调），避免"定位冻结"特征
   - **到达终点**后同样保持终点定位并提示；点「重新开始」从头播放，点「停止」才恢复真实定位
5. 点「停止」移除测试 Provider，恢复系统真实定位

## 4.1 路线库

- 首次启动会内置「田径场（示例）」（5 个点 + 首尾相连，共 6 个路径点），可直接载入
- 内置坐标已做坐标系校正，详见 6.8

## 4.2 坐标系说明（重要）

国内地图（高德/腾讯）用 **GCJ-02**（"火星坐标"），GPS/Android Location 用 **WGS-84**，两者相差 400–600 米。

- 本 App **内部统一用 WGS-84** 存储与注入（这样注入的位置就是真实 GPS 语义）
- 使用高德底图显示时，临时把 WGS-84 转成 GCJ-02 → 与你在地图上看到的位置完全重合
- 在地图上点选/拖动得到的是 GCJ-02，会先转回 WGS-84 再保存
- 切换到 OSM/Carto 等境外底图时自动按 WGS-84 显示，无需手动处理

> **坐标核对结论（已用高德卫星图逐点验证）**：你提供的 JSON 中
> **`glat/glon` 才是 GCJ-02 地图坐标** —— 叠到高德卫星图上正好落在一个标准田径场+足球场上；
> 而 `lat/lon` 比它多出约 (+0.0061, +0.0065) 的常数偏移，会落到旁边的山林里。
> App 现在以 `glat/glon` 为权威输入 → 转成 WGS-84 存储/注入 → 显示时转回 GCJ-02，
> 因此路线与你在高德上看到的操场完全重合。


- 菜单 →「保存当前路线」→ 起个名字存入路线库（可覆盖同名）
- 菜单 →「路线库」→ 点条目载入到主界面；「删除…」可清理
- 开工向导的第 ② 步直接从路线库读取

## 5. 导入 / 导出路径

菜单 → 导入 GPX：支持标准 `<trkpt lat lon>` 轨迹文件（可先用高德/两步路/Google Earth 画路线导出 GPX）
菜单 → 导出 GPX：把当前路径导出，方便复用

## 6. 菜单设置

菜单 → 设置：

| 项 | 说明 |
|---|---|
| 基础海拔（米） | 路径点没写海拔时使用；默认 50 m |
| 接管 Provider | `gps` / `network` / `fused` 多选；默认 gps+network |
| 拟真模式 | 位置 1–2 m 漂移、速度/精度/朝向噪声、GNSS 卫星数/载噪比、起步 2 秒缓动（默认开） |

- `fused`：Google Play Services 融合定位，国产 ROM 上一般无效，开启有极小概率影响 GMS 行为
- Provider 与拟真模式的改动在**下次开始**时生效

## 6.1 海拔

- 全局基础海拔：设置里填写的值
- 逐点海拔：GPX 里带 `<ele>` 时会自动读取；导出 GPX 也带海拔
- 播放时若路径点未指定海拔，用基础海拔；相邻点都有海拔则线性插值
- 注入字段：`altitude`、`verticalAccuracy`，Android 14+ 同时写 MSL 高度

## 6.2 悬浮窗

菜单 → 「悬浮窗」（需先允许"显示在其他应用上层"）：

- 播放/临时定位时在其它应用上层显示：**状态 + 速度 / 里程 + 海拔 + 卫星数**
- 可拖动到任意位置并记住位置；带「暂停 / 继续」「停止」按钮
- 再点一次菜单项关闭；服务停止时自动隐藏

## 6.3 基站 / Wi-Fi 环境模拟（需要隐藏模块 v0.4.0+，并已加入 LSPosed 作用域）

| 模式 | 行为 |
|---|---|
| 回放（默认，指纹与目标位置 ≤30 km） | 目标 App 读到的基站/Wi-Fi 是采集到的环境快照 |
| 隐藏（无快照 / 距离过远） | 目标 App 读到空基站列表、`getCellLocation()` 为 null、Wi-Fi 扫描为空 |

注意：
- 必须把目标 App 加进隐藏模块的 LSPosed 作用域，否则不会生效
- 基站数据依赖运营商与信号，室内/无 SIM/飞行模式下可能采集不到，此时建议用「隐藏」
- 目标 App 若把数据传给服务端做反查，仍可能被识破（见 `docs/mock-detection.md`）

## 6.5 速度混淆与目标配速

菜单 →「目标配速…」，**全部用选择器**，时间自动计算：

| 选择项 | 可选值 |
|---|---|
| 单圈距离 | 200 / 300 / 350 / 398（标准跑道）/ 400 / 500 / 800 / 1000 m |
| 目标距离 | 1 / 2 / 3 / 5 / 10 km、半程马拉松 21.1 km |
| 目标配速 | 3:00–10:00 /km 共 12 档 |
| 最大速度 | 8 / 10 / 12 / 14 / 15 / 16 / 18 / 20 km/h |

对话框底部实时显示自动计算结果，例如：
```
圈数：3 圈（计划 1.05 km）
实际距离：1.04 km · 目标时间：6:14
平均速度：10.0 km/h · 上限：15 km/h
```

规则：
- **圈数 = ceil(目标距离 ÷ 单圈距离)**，实际距离 = 圈数 × 当前路线一圈的实际长度
- **目标时间 = 实际距离 ÷ 配速**（不用手填时间，避免自相矛盾）
- 播放时按分段随机速度，总时长误差 ≤10 秒；单段速度 ≤ 平均速度 ×1.25，且 ≤ 最大速度
- **速度只有一个来源**：启用目标配速后，主界面隐藏「速度」滑块与「循环播放」，速度完全由配速决定
- 若配速对应速度超过最大速度（例如 3:00/km 需 20 km/h 而上限 15），保存时弹「目标不可达」，给出最快完成时间，可选择返回修改或仍然启用（按上限跑）
- 若当前路线一圈长度与所选单圈差距 >2%，预览会提示，并按路线实际长度计算

关闭目标配速后，主界面的速度滑块恢复，按滑块速度 + 速度混淆播放。

## 6.6 预设路线

菜单 →「预设路线…」（或开工向导里「预设路线」），以**地图中心 / 目标位置**为锚点一键生成：

| 预设 | 长度 |
|---|---|
| 标准 400m 跑道 | 398 m（两直道 + 两半圆） |
| 800m 圆形环线 | 800 m |
| 2km 矩形环线 | 2000 m（600×400） |
| 3km 矩形环线 | 3000 m（1000×500） |
| 1km 直线 | 1000 m |
| 2km 直线往返 | 2000 m |

- 生成后可继续拖动图钉微调、保存到路线库
- 开启目标配速时，加载预设会自动把「单圈距离」同步成该预设的实际长度
- 已有路径时替换会先二次确认

## 6.7 步数 / 步频 / 步幅

- 默认速度 6 km/h（快走）；步频上限 210 步/分、步幅上限 1.5 m（约对应 18 km/h 冲刺）
- 模拟播放时按**时变步态模型**推算：
  - 基础步幅 = clamp(0.55 + 0.18 × 速度) 米 × 本次模拟个体系数（0.94–1.06）
  - 慢变漂移：均值回归随机游走，幅度 ±10%（步频会慢慢变快/变慢）
  - 呼吸周期：25–45 秒正弦波动 ±3%
  - 每步步幅独立抖动 ±4%，因此**同一次模拟里步频和步幅都不会恒定**
  - 步频 = 速度 ÷ 步幅 × 60 × (1 + 漂移 + 呼吸)，典型 105（走）~175（跑）步/分
  - 步数按"逐步累加"（每步所需距离单独抖动），只增不减
- 界面显示：状态栏「步 N（X 步/分）」、里程行「步幅 0.xx m」、悬浮窗「步 N（X 步/分）」
- 典型值：步行 1.4 m/s → 约 105 步/分、步幅 0.8 m；跑步 3.5 m/s → 约 170 步/分、步幅 1.15 m
- 模块会把数据回放到目标 App：hook `SensorManager` 的 `STEP_COUNTER` / `STEP_DETECTOR` 监听
  - 真实回调的 `values[0]` 被替换成我们的累计步数
  - 按步频合成 `STEP_DETECTOR` 事件（每个事件 1 步）
  - 暂停/停止移动时步频归零、步数冻结；彻底停止后不再干预（透传真值）
- 覆盖范围：影响通过 `SensorManager` 读计步的 App；**不影响** Health Connect / Google Fit 历史数据、
  厂商健康 SDK、`SensorDirectChannel`

### 步数/步频没生效时的自检（v0.16.3+）

菜单 →「**模块状态与启用步骤**」会显示：LSPosed 管理器是否安装、模块是否已注入目标 App、
目标 App 是否正在读取步数，并给出逐步操作说明；点悬浮窗第二行也能跳到主界面看这份状态。

模拟运行时主界面状态栏会显示三种状态之一：

| 状态 | 含义 | 该怎么办 |
|---|---|---|
| `模块未注入` | LSPosed 没启用模块 / 作用域没勾目标 App / 勾了但没重启目标 App | 到 LSPosed 启用「虚拟运动」→ 作用域勾目标 App（含多进程包的每个进程）→ 强制停止目标 App 再打开 |
| `模块已注入（目标App未读传感器）` | 模块已在目标进程，但该 App 不读 `SensorManager` 计步（微信运动/支付宝运动多走系统健康数据或服务端） | 这类 App 无法用本方案伪造，只能换成自己读传感器的运动类 App |
| `模块读取中 Ns前` | 正常回放中 | 若步数仍不对，问题在目标 App 的换算/过滤逻辑，可反馈 App 名 |

另外目标 App 自身需要「活动识别 / 健身运动」权限才能注册计步传感器，没授权时它也读不到步数。

### IMU 伪造（加速度计 / 陀螺仪）

模块同时接管 `ACCELEROMETER`、`LINEAR_ACCELERATION`、`GYROSCOPE`、`GRAVITY` 四类传感器（50Hz 合成）：

| 传感器 | 波形 |
|---|---|
| 加速度计 | z = 9.81 + A·sin(2πf·t)，A 随速度 2（走）→ 6–9（跑）m/s²，x/y ±0.15 噪声 |
| 线加速度 | 加速度 − 重力 |
| 重力 | ≈ (0, 0, 9.81) 含微小噪声 |
| 陀螺仪 | x/y 与步频同相摆动，z = 路线转向角速度（弯道时非 0） |

- 相位按"步频增量"累加（步频变化时波形平滑不跳变）
- 停止/暂停移动时只剩重力、陀螺仪接近 0
- **重力/加速度已按姿态自洽**：重力方向由当前姿态（20° 基础俯仰 + 摆动）旋转得到，
  因此 App 用 `getRotationMatrix(accel, mag)` 反推的倾角与旋转矢量一致

### 姿态类传感器（ROTATION_VECTOR / MAGNETIC_FIELD，按跑步摆动）

| 传感器 | 生成方式 |
|---|---|
| `ROTATION_VECTOR` | 四元数：航向 = 路线航向（弯道跟随），叠加每步摆动：俯仰 6–22°、侧倾约一半、偏航 ±5°（静止时只剩基础姿态 20° 俯仰） |
| `MAGNETIC_FIELD` | 地磁矢量 (0, 29, −41) µT 随姿态旋转，模长恒约 50 µT；朝北时水平分量在设备 y 轴，朝东/朝西转到 x 轴且反号 |

- 摆动与加速度/陀螺**同相位**（共用步频相位），步频变化时相位连续
- 设置 →「伪造姿态传感器」可关闭（默认开启）；关闭后透传真实值
- **风险**：开启后目标 App 的指南针方向会变成虚拟航向，AR/相机取景、部分 ROM 的横竖屏判断可能异常
- 也已接管 `GAME_ROTATION_VECTOR`（无磁力计四元数，偏航基准每进程固定随机偏移 ±180°，不暴露真实航向）
  与 `ORIENTATION`（方位角/俯仰/滚转三元组，方位角跟随路线航向）
- 未接管 `PRESSURE`、`PROXIMITY` 等非姿态传感器

## 6.8 悬浮窗与停止语义（重要）

**主界面「开始」（第一段）**：启动前台服务 + 自动弹出悬浮窗 + **只把定位定到路线起点并保持**，路线不移动。
状态显示「已定位到起点（待开始）」。

**悬浮窗上的三个按钮**：

| 按钮 | 行为 |
|---|---|
| 开始 | **开始路线模拟**（第一段在主界面已经定位到起点） |
| 暂停 | 暂停移动，**定位保持在当前位置**（仍持续上报，不会恢复真实定位） |
| 停止移动 | 停止路线模拟，**定位保持在当前位置**，悬浮窗显示「已停止移动 · 定位保持」 |

**悬浮窗还会显示**：
- 第一行：状态（已定位起点 / 运行中 / 已暂停 / 已停止移动 / 已到达）
- 第二行：模块自检（`模块读取中 Ns前` / `模块已注入（目标App未读传感器）` / `模块未注入`）
- 第三行：里程 · 海拔 · 步数与步频
- **点标题行（或右侧 ▾/▸）可折叠/展开**，折叠后只保留一行状态，位置会记住

**到达目标时的自动停止（v0.19.3 起，默认开启）**：跑到目标距离或配速计划跑完时，
悬浮窗与主界面先显示「已到达」，2.5 秒后 App **自动彻底停止并恢复真实定位**，不需要再手动点按钮。
设置里可关闭这个行为（关闭后定位冻结在终点、持续上报，需要手动「彻底停止」才会恢复真实定位）。

**手动「彻底停止」**：回到 App 主界面点「彻底停止」会移除模拟定位、恢复手机真实定位；
点击时会先弹确认框，明确提示"悬浮窗的暂停/停止移动只冻结位置"。

主界面状态会同步显示：`已停止移动（定位保持）`，按钮变成「继续 / 彻底停止」。

## 6.9 悬浮窗权限被拒怎么办

部分系统（小米/红米/部分 ColorOS）把「显示在其他应用上层」列为**受限权限**，直接授权会弹
「系统已拒绝向此应用授予访问权限」。处理步骤：

1. 菜单 →「悬浮窗」→ 弹窗里点「应用信息」
2. 应用信息页右上角 ⋮ → **允许受限制的设置**

## 6.10 Root 检测

- 主界面顶部有 `Root：…` 状态行，**点一下可重新检测/申请授权**（会弹出 Magisk/KernelSU/APatch 授权框）
- 开工向导顶部也有「检测 / 申请 Root 授权」按钮与状态
- 未获得授权时点「开始」会提示先授权；授权后重新检测即可
- 若一直失败：确认 root 管理器里本应用未被拒绝/加入拒绝名单，再点一次检测

## 6.11 GNSS 卫星状态回放（v0.19.0+）

目标 App 里查卫星状态（`LocationManager.registerGnssStatusCallback` / `GnssStatus`）时，
看到的是**你这个位置、这个时刻真实可见的那批卫星**，不再是随机一套：

- 星表来自 CelesTrak 公开 TLE（GPS / GLONASS / Galileo / 北斗，共 143 颗），随 APK 内置
- 每颗卫星的位置由 TLE 根数 + J2 摄动推算，再算成相对目标位置的仰角 / 方位角
- 只上报仰角 > 3 度的卫星：**北京和广州看到的集合不同**，同一地点不同时刻卫星会升落、数量自然变化（通常 30–70 颗）
- 卫星的 Svid / 星座 / 载噪比 / 是否参与定位都来自真实几何；参与定位的颗数与注入 `Location` extras 的 `satellites` 一致
- 模块按 1 Hz 投递；主 App 停止模拟或拟真模式关闭时，自动回落到真实卫星状态（不做任何改写）

前提：目标 App 已加入 LSPosed 作用域并重新打开；主 App 正在模拟且「拟真模式」开启；
`assets/gnss_tle.txt` 在有效期内（建议每 1–2 个月执行 `python3 scripts/update_gnss_tle.py` 刷新，
过期 45 天后 App 日志会给出警告，位置误差会随时间变大）。

自检：LSPosed 日志过滤 `VLocHidden`，应看到 `gnss hooks=15/15`、`gnss replay active: satellites=N, rate=1Hz`；
主 App 日志 `VLocService: gnss catalog=143 tleAgeDays=N`。

> 仍未覆盖：`GnssMeasurements`、`GnssNavigationMessage`、NMEA 句子（`$GPGGA`/`$GSV`）以及
> system_server / 其它进程看到的卫星状态。
> 另：GLONASS / Galileo 的 Svid 是按 NORAD 编号稳定派生的（TLE 名称里没有 PRN），
> 真实 PRN 需要额外映射表；几何是真实的，编号仅保证同星座内不重复且落在 Android 惯用区间。

## 6.12 虚拟摄像头（v0.20.0+，独立悬浮窗 v0.22.0+）

菜单 →「虚拟摄像头…」：

- **添加视频**：从相册选择（可多选），主 App 会记住读取授权；可删除、可点某个视频设为当前
- **启用开关**：默认关闭；关闭时对相机完全无影响
- **独立悬浮窗（v0.22.0）**：打开开关并保存后，屏幕上出现胶囊
  `📹 虚拟摄像头 开 · 1/2 视频名  ✕`（需要「显示在其他应用上层」；未授权会弹权限引导）
  - **点文字**：切换到下一个视频
  - **长按**：开 / 关虚拟摄像头（关闭后胶囊自动消失）
  - **点 ✕**：只收起胶囊，摄像头保持启用（下次启用或重新打开主界面不会硬弹回来；在菜单里再保存一次即恢复）
  - **拖动**：位置单独记忆，不与定位悬浮窗共用坐标
  - 定位会话（播放/定点）运行时不显示胶囊，由定位悬浮窗那行统一显示相机状态；会话结束后自动交还
- **定位悬浮窗折叠行**：定位会话期间显示 `📹 虚拟摄像头 开 · 1/2 视频名`，点一下切换、长按开关

> **视频添加**：摄像头页「添加视频」从相册多选即可（无需打包进 APK），添加时会提示时长是否在 60–120 秒。
>
> **点间距说明**：注入点按时间产生，间距 = 速度 × 间隔；v0.32 起 10Hz（100ms），
> 6 km/h ≈ 0.17 m/点、12 km/h ≈ 0.33 m/点。真机 GPS 普通 1Hz、最高约 10Hz，
> "每几厘米一个点"需要 50Hz 以上，实际设备和 App 采样都做不到；轨迹平滑主要靠低噪声 + 连续速度。
>
> **两套传感器逻辑（重要）**：摄像页有开关「接管时 IMU 固定为竖直静止」——
> 开（默认）：目标 App 看到手机竖直静止，适合运动/姿态检测类 App；
> 关：接管期间继续按「运动模拟」的跑步姿态回放，适合跑步类 App。两者互斥，别同时期望。
>
> 预置视频：把 `jump_rope.mp4`（跳绳 ≥100 个 / >1 分钟）和 `jumping_jacks.mp4`（开合跳 >20 个 / >1 分钟）
> 放进 `app/src/main/assets/camera_presets/`，App 首次启动会自动加入列表；每段时长需 60–120 秒。
>
> v0.23.1 起已修复"接管不生效"的根因（模块读 Provider 时列索引错误，导致一直判定未启用）。
> v0.21 起模块侧已实现（实验性）：目标 App 内相机预览会被替换成选中视频；拍照会返回视频帧
> （YUV 格式的 ImageReader 生效；直接要 JPEG 的 App 暂不支持）。
> **需要把目标 App 加入 LSPosed 作用域并重启目标进程**，并在菜单里打开「虚拟摄像头」开关。
> 控制页顶部还有**接管诊断**：显示"模块是否注入 / hook 数 / 是否拦到相机会话 / 是否开始渲染 / 最后错误"，
> 不用抓日志就能判断卡在哪一步（未上报 = 未注入或没开相机；已注入但无会话 = 目标 App 可能走 Camera1/NDK）。
> 自检：`logcat | grep VLocHidden` 里出现 `camera hooks=9/9`、`camera replay active: clip=1/N`、
> `camera session intercepted`、`camera replay started: 1920x1080`。
> 如果目标 App 相机黑屏/异常：先在菜单里关掉虚拟摄像头（或长按悬浮窗那行），相机 1 秒内恢复真实画面。

## 7. 常见问题

**Q: 开始后目标 App 位置没变？**
- 确认目标 App 已完全退出后重启（部分 App 缓存 last known location）
- 确认状态栏 `Root：已授权 ✓`
- 试着在设置里多勾选一个 Provider

**Q: 目标 App 提示"检测到模拟位置"？**
阶段一注入的坐标会被系统标记为模拟位置。安装 `hidden` 模块（阶段二，LSPosed）后
可在目标 App 进程内隐藏该标记，见 `docs/phase2-hidden.md`。

**Q: 地图一片空白？**
OSM 瓦片需要联网，国内网络可能较慢；换网络或等待重试即可。

**Q: 停止后定位不恢复？**
点「停止」会执行 `removeTestProvider`。若 App 被强杀导致 Provider 残留，
重新打开 App 再点一次「停止」，或重启手机。
